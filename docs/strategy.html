DTI — Distance-Weighted Tversky

Source: Problem description § Performance metric

TI(α,β) = Σ p(x)g(x) / [Σ p(x)g(x) + α Σ p(x)(1-g(x)) + β Σ (1-p(x))g(x)]

Distance-weighted with triangular kernel k(d)=max(1-d/R,0), R=300m=3px:

  • TP_w = Σ_g∈G max_{x:d(x,g)≤R} p(x) k(d(x,g))
  • FP_w = Σ_{x:p(x)>0} p(x)[1-max_g k(d(x,g))]
  • FN_w = Σ_g∈G [1-max_{x:d≤R} p(x)k(d)]
  • DTI(α,β)=TP_w/(TP_w+α FP_w+β FN_w+ε), α=0.2 β=0.8

Implementation in src/gems/metric.py matches official, verified against reference solution gems-prize-reference-solution.

Placement Beats Mass — Pindrop Insight

From GEMSDOE3: metric credits truth pixel from single best prediction inside 300m kernel, so dense trace pays several times for one coverage. Official metric is coverage function with pixel budget — cheapest optimal set is spaced nodes at kernel spacing.

Kernel radius R=3px (300m), largest spacing that cannot lose coverage at midpoint: spacing/2 < R → spacing ≤5px, published spacing 4px → worst-case gap 2.0px <3.

Implementation: rank candidates by confidence, accept only when no accepted node inside suppression square half-width spacing-1. Spacing=1 suppresses nothing, so control is dense ridge prefix that confidence floor would emit. Only changed parameter between published file and control is that number.

GEMSDOE9 uses top 2.8% but with oriented lineament simulation, not dense ridge — distinct placement.
