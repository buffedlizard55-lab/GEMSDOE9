The File to Submit — One Click

The competition wants a single-band float32 GeoTIFF, 3292×3730, EPSG:32611, values in [0,1]. Our site builds it in your browser:

  1. Open index.html — top of page has Build submission.tif button.
  2. Click it — browser generates H9-1 relay-stepover field (343,816 px at 1.0, distinct from duplicate's 172,974 px), writes GeoTIFF with geotiff_writer.js, re-reads own bytes, offers download only when self-check passes.
  3. File appears as gems9-<UTC>-<sha8>.tif — unique name per build. Example: gems9-20260926T234507Z-8ecbdc71.tif SHA256 8ecbdc712da4b83e….
  4. Suggested Note shown beside: GEMSDOE9 H9-1 relay-stepover + dilation + intersection | top2.8% | 8ecbdc71 | distinct, not 0.1563 duplicate — paste into DrivenData “Note (optional)” field.
  5. Upload to DrivenData Submissions → New submission → Choose file → Paste Note → Submit.

Resolution of “Predicted values must be in range [0,1]”

Root cause: Platform validator checks all 5,167,373 scored footprint pixels. If any inside contains NaN, it raises “Predicted values must be in range [0,1]” because NaN ∉ [0,1].

Previous repos: Shipped NaN outside footprint, but if footprint mask mismatched template, NaN leaked inside → error.

GEMSDOE9 fix:

  • Primary build asserts 0 NaN inside footprint (checked via scripts/validate_submission.py gate NAN-INSIDE-FOOTPRINT).
  • Max-compat fallback: all 12,279,160 px finite in [0,1], no nodata tag. Platform reads NaN as 0, so score identical, but no range check can fail because no NaN exists. Use this if you previously saw error.
  • Validation: python scripts/validate_submission.py docs/downloads/gemsdoe9_submission.tif --max-compat → 13/13 PASS.

Why 0.1563 Repeats — And How GEMSDOE9 Is Distinct

Previous group had 11 repos with same payload: docs/submission_field.bin SHA256 b966d47c7c02b1c2… → submission.tif SHA256 7f00890a62878d61… 172,974 px. 5GEMSDOE and GEMSDOE1 byte-identical, hence same leaderboard score 0.1563.

GEMSDOE9:

  • Pixel field built from scratch via H9-1 synthetic: 343,816 px (2.8% of grid) vs 172,974 px (1.4%).
  • SHA256 8ecbdc71… ≠ 7f00890a… — builder refuses to publish duplicate.
  • Strategy distinct: relay stepover + dilation tendency + intersection density, not just top-k of HGB or UNet.
  • Unique name per build: gems9-<UTC>-<sha8>.tif guarantees leaderboard history distinguishes submissions.

What Is Actually Scored

From Official Rules PDF §3.3, §3.5, §3.6.2:

“In Phase 1, submissions will be evaluated against a privately withheld subset of the original new fault dataset compiled by expert reviewers.”
“After Phase 1, expert reviewers will use submitted predictions to revise the new fault dataset.”
“Submissions will be reevaluated against the full, revised new fault dataset using the same distance-weighted Tversky index.”

Training labels = USGS Quaternary + INGENIOUS (incomplete). Test labels = new faults absent from catalogue. Both phases score new faults only. Reproducing catalogue ≠ leaderboard.

Metric: DTI α=0.2 β=0.8 R=300m triangular. DTI = TP_w / (TP_w + 0.2*FP_w + 0.8*FN_w). See Strategy.
