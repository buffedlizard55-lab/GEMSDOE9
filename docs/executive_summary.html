EXECUTIVE SUMMARY / SUBMISSION PLAYBOOK

The GeoTIFF is easy. Earning an upload is the hard part.

The site contains a generated, checked GeoTIFF to demonstrate the pipeline. It is not approved for contest upload: it failed the local holdout. The competition's private fault labels are inaccessible.

No weekly submission slot should be spent on G9 basin-v1. The candidate's 0.02947 catalogue-proxy DTI is below three equal-budget random controls (0.16678–0.17137) and below gravity-only (0.04219). Do not mistake file validity for scientific skill.

When a future candidate passes the gate

01

Generate a unique file

On a machine with the verified rasters: bash scripts/download_competition_data.sh, .venv/bin/python scripts/gems9.py evaluate, and only for research .venv/bin/python scripts/gems9.py build-experimental --output reports/basin-experimental.tif. Never rename an old candidate to pretend it is new. Pin code, model settings, input hashes and raster hash in a release ledger.

02

Run both gates, not just a validator

Holdout: same folds, truth regime, metric and pixel budget as the best prior method, no training on test labels, and distinct artifact SHA/field. Format: .venv/bin/python scripts/gems9.py validate --output path/to/file.tif verifies every pixel against the supplied template. The official submission specification requires single-band float32 values in [0,1], EPSG:32611, 100m resolution, matching bounds and NaN/null outside. Our template measures 3292 columns × 3730 rows. The output keeps 5,167,373 finite in-footprint cells, 7,111,787 outside NaNs; an invalid value inside must abort.

03

Upload only an approved artifact

On DrivenData's authenticated submission page, choose the .tif (or a ZIP containing just that one TIFF) under “File to submit.” Paste a unique short Note, for example G9 basin-depth-gravity sigma2 3pct sha-ae3ec2c5 only as a formatting example; do not submit this failed candidate. Submit through your authorized competition account; record date, SHA256, note and actual displayed score. We cannot log in, upload or claim a result.

04

If “Predicted values must be in range [0, 1]” appears

Do not blindly clip. Verify the submitted file is the checked SHA, its inside-template cells are all finite and in [0,1], and outside cells match template nulls. Our validator enforces those requirements. The error may reflect an in-footprint NaN or different backend validation behavior; the exact cause of the user's earlier rejection has not been reproduced because the rejected uploaded bytes are unavailable. If a locally validated file is rejected, save its hash and exact error, check the official rules/forum and contact DrivenData support; do not use a weekly slot to probe undocumented behavior.
