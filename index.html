How this fixes “Predicted values must be in range [0,1]”

Root cause: Platform validator inspects all 5,167,373 scored footprint pixels. If any pixel inside this footprint contains NaN, it raises “Predicted values must be in range [0,1]” because NaN is not in [0,1].

GEMSDOE9 fix: We ship two variants:

  • Primary (spec): finite inside footprint, NaN outside, nodata=nan — enforced by scripts/validate_submission.py.
  • Max-compat (fallback): all 12,279,160 pixels finite in [0,1], no nodata tag, 0 outside. Under official scorer, NaN is read as 0.0, so both score identically, but no range check can complain about NaN because there is none. Use this if dialog previously rejected file.

Builder asserts 0 NaN inside footprint before offering download. Re-run validation yourself: python scripts/validate_submission.py docs/downloads/gemsdoe9_submission.tif --max-compat
